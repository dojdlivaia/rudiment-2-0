# Инструкция по публикации на GitHub Pages

## Быстрый старт

### 1. Создай репозиторий на GitHub

1. Зайди на https://github.com/new
2. Введи имя репозитория (например, `rudiment-2.0`)
3. Выбери **Public** (публичный)
4. **НЕ** ставь галочку "Add a README file" (он уже есть)
5. Нажми **Create repository**

### 2. Запушь код

Открой терминал в папке проекта и выполни:

```bash
# Инициализация Git
git init

# Добавь все файлы
git add .

# Первый коммит
git commit -m "Initial commit: Рудимент 2.0"

# Создай главную ветку
git branch -M main

# Добавь удалённый репозиторий (замени USERNAME и REPO на свои)
git remote add origin https://github.com/USERNAME/REPO.git

# Запушь код
git push -u origin main
```

### 3. Настрой GitHub Pages

1. Зайди в настройки репозитория: `https://github.com/USERNAME/REPO/settings`
2. В левом меню выбери **Pages**
3. В разделе **Build and deployment**:
   - **Source**: выбери **GitHub Actions**
4. GitHub автоматически задеплоит сайт при следующем push

### 4. Дождись деплоя

1. Перейди во вкладку **Actions** в репозитории
2. Увидишь запущенный workflow "Deploy to GitHub Pages"
3. Дождись завершения (обычно 1-2 минуты)
4. Когда появится зелёная галочка — сайт готов!

### 5. Открой сайт

Твой сайт будет доступен по адресу:
```
https://USERNAME.github.io/REPO/
```

Например: `https://ivanov.github.io/rudiment-2.0/`

## Обновление сайта

Просто запушь изменения в ветку `main`:

```bash
git add .
git commit -m "Update: описание изменений"
git push
```

GitHub Actions автоматически пересоберёт и задеплоит сайт.

## Решение проблем

### Сайт не открывается

1. Проверь, что workflow завершился успешно (вкладка Actions)
2. Убедись, что в Settings → Pages выбран Source: **GitHub Actions**
3. Подожди 5-10 минут после первого деплоя

### Ошибка сборки

1. Проверь логи в вкладке Actions
2. Убедись, что все зависимости установлены: `npm install`
3. Проверь, что проект собирается локально: `npm run build`

### Старая версия сайта

1. Очисти кэш браузера (Ctrl+Shift+R или Cmd+Shift+R)
2. Проверь, что push был в ветку `main`
3. Дождись завершения workflow

## Кастомный домен (опционально)

Если хочешь использовать свой домен:

1. В Settings → Pages укажи свой домен
2. Создай файл `CNAME` в корне репозитория с именем домена
3. Настрой DNS у регистратора домена

Пример `CNAME`:
```
cognition.example.com
```

## Важно

- Данные пользователей сохраняются в **localStorage** браузера
- Данные привязаны к конкретному браузеру и устройству
- При очистке кэша данные удалятся
- Для синхронизации между устройствами нужна база данных
